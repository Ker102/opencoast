# OpenCoast への貢献

地図やソフトウェアの改善にご協力いただきありがとうございます。報告された観察、引用された法律上の規則、モデレーターが審査した結論の違いを明確にしてください。

<a id="choose-where-to-contribute"></a>

## 貢献先を選ぶ

| 協力したい内容 | 最初の手順 |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| ビーチ、海岸エリア、ルート、入口、訂正 | [地図を開き](https://opencoast-web.vercel.app/)、Add information またはレコードの訂正操作を使います。 |
| 公的出典と地域のアクセス条件 | 関連する地図上の主張とともに出典を提出してください。[モデレーション方針](docs/moderation-policy.md)で評価方法を確認できます。 |
| ソフトウェアの不具合や機能 | [既存の issue](https://github.com/Ker102/opencoast/issues)を検索してから、[issue を作成](https://github.com/Ker102/opencoast/issues/new/choose)します。 |
| コード、文書、アクセシビリティ | [開発ガイド](docs/development.md)と下記のコード貢献手順を読んでください。 |
| セキュリティ脆弱性 | [非公開の脆弱性報告](https://github.com/Ker102/opencoast/security/advisories/new)を使います。 |

地図情報の提出に GitHub アカウントは不要です。GitHub は開発への貢献に使用し、地図には独自のモデレーター審査フローがあります。

<a id="map-information"></a>

## 地図情報

アプリの **Add information** からエリア、ルート、ポイント、訂正を提案できます。アカウントは不要です。できる限り正確な形状、管轄区域、許可されると考える内容、関連条件、観察または読んだ内容の説明を含めてください。公的文書と直接リンクは強く推奨しますが任意です。公的出典のない提出も審査でき、その旨を示すラベルを表示します。審査を追跡しモデレーターに回答するため、非公開の受付リンクを保存してください。

<a id="what-makes-a-useful-submission"></a>

### 有用な提出に必要なもの

- 場所を特定し、主張に関係するエリア、ルート、ポイントだけを描きます。
- 関連する国や管轄区域と、コンセッションや海岸の小道など地域の分類を示します。
- 活動と条件、日付、季節による制限、不確実性を説明します。
- 文書の場合は、直接の出典リンク、題名、発行機関、日付、入手できる場合は関連条項やページを含めます。主張のどの部分を裏付けるか説明します。
- 個人的な観察の場合は、いつ何を見たのかを説明します。観察と法的権利についての結論を区別してください。
- 岸辺へのルートは、到達する海岸エリアとは別に提出します。モデレーターが各レコードを審査し、明示的に関連付けます。

世界中からの提出を歓迎します。公的出典がなくても有用な記述は、モデレーション後にコミュニティ審査ラベル付きで公開できます。一般的な規則だけに基づく推測で広い地域を埋めないでください。

説明や公開 issue に氏名、顔、電話番号、非公開の連絡先を載せないでください。アップロード原本はモデレーターだけが閲覧できます。画像公開への同意は任意であり、公開を保証しません。

<a id="code-changes"></a>

## コード変更

1. 作業前に既存の issue と pull request を検索します。
2. 大きな機能や不具合については、期待する動作を議論できるよう issue を作成します。
3. ブランチを作成して対象を絞った変更を行い、[開発ガイド](docs/development.md#checks)の関連検証を実行し、pull request を作成します。
4. 変更内容、理由、テスト内容、アクセシビリティやプライバシーへの影響を説明します。

リポジトリは npm workspaces を使用します。`shared` はデータ契約、`api` は永続化とモデレーション、`web` は地図インターフェースを担当します。公開エンドポイントは、未審査提案、受付トークン、証拠原本、モデレーターの認証情報、投稿者の身元を決して公開してはいけません。新しい地図状態には対応する凡例と詳細説明が必要です。

法律上の出典には再利用制限がある場合があります。リンクを示し、自分の言葉で要約してください。法律全体を貼り付けたり他の地図のデータをこのリポジトリにコピーしたりしないでください。OpenStreetMap の帰属表示は見える状態を保つ必要があります。本番の初期データに海岸アクセスの主張例を追加しないでください。

<a id="reporting-security-issues"></a>

## セキュリティ問題の報告

セキュリティ問題は公開 issue ではなく GitHub の非公開脆弱性報告を使ってください。最小限の再現手順を含め、実際の受付リンク、証拠ファイル、認証情報の公開は避けてください。
