# OpenCoast モデレーション方針（初期版）

<a id="review-each-claim-as-a-claim"></a>

## 各主張を主張として審査する

地図は提出された証拠が裏付ける内容を記述します。モデレーターは公開前に提案の場所、正確な形状、管轄区域、文言、条件、出典リンクを確認します。事業者に退去を求められたという報告は観察であり、それだけで法的境界や権利の証明にはなりません。賃貸やコンセッションは条件を課しても、海岸全体をアクセス不能にするとは限りません。文書で裏付けられた法的権利と観察された妨害は別々に記録できます。

国全体の規則だけを理由に海岸を色付けしません。提出された境界は、権威ある形状データを取得して別途確認するまで**概略**のままです。ビーチエリアは陸路アクセスを確定しません。ルートを独立レコードとして審査してください。

接近ルートは、実際にエリアへ到達することを確認したモデレーターが明示的に関連付ける必要もあります。関連付けには監査理由を記し、エリアの公開改訂履歴に表示します。関連ルートが検証済み陸路として扱われるのは、現在のレコードが公開され、文書の裏付けがあり、許可または条件付きとされている間だけです。コミュニティ審査済み、争いあり、制限あり、不明のルートは関連情報として表示できますが、接近路を検証したことにはなりません。ルート状態が変わればエリアの陸路ラベルも更新されます。関連する形状を移動する前にリンクを解除し、関係を再確認できるようにしてください。

<a id="evidence-labels"></a>

## 証拠ラベル

- **文書による裏付けあり：** リンクされた公的出典を少なくとも一つ、主張と形状に照らして確認済みです。関連条項をモデレーター説明で引用または要約してください。不確かな境界と例外を説明します。
- **コミュニティ審査済み、公的出典の検証なし：** モデレーターは表示する価値のある説明と判断しましたが、公的出典は検証していません。ラベルを目立つように保ってください。法的結論を確実なものとして述べないでください。

アクセス状態（`allowed`、`conditional`、`restricted`、`disputed`、`unknown`）は証拠の強さと別です。文書化された制限には**条件付き**、信頼できる証拠の矛盾には**争いあり**、実際の規則を確定できない場合は**不明**を使います。却下はアクセス禁止を意味しません。

<a id="review-steps"></a>

## 審査手順

1. 説明全体を読み、適切なズームで描かれた地物を調べます。無関係な土地や水域を覆っていないか確認します。
2. 出典リンクを開き、発行機関、日付、対象範囲、改正や失効を確認します。実際に確認した内容を記録してください。
3. 非公開アップロードの関連性、真正性の手がかり、顔、氏名、位置メタデータ、公開許可を調べます。原本を公開しないでください。アプリは公開同意のある画像からメタデータ除去済み JPEG を作成できますが、モデレーターは画像に見える内容も確認する必要があります。
4. 近くの公開レコードや未審査提案と重複・矛盾がないか確認します。情報不足なら追加説明を求めます。
5. 必要に応じて正確な文言に編集し、監査理由を記します。アクセス状態と証拠ラベルは別々に選びます。
6. 主張を表示する理由と残る不確実性を短い公開説明にまとめます。上記の確認後にのみ公開画像を選びます。承認、理由付きの却下、または追加説明の依頼を行います。

初期のモンテネグロの登録と争いのある主張は、宣伝前に別の独立したモデレーターが法律上の出典と形状を確認するよう依頼してください。異議のあるレコードは再確認中に停止するか、争いありと表示してください。出典日と審査日を最新に保ちます。編集日だけでは新しい法律審査を意味しません。

<a id="privacy-and-conflicts"></a>

## プライバシーと利益相反

受付トークン、投稿者の身元、非公開メッセージ、原本文書、未承認写真を決して公開しないでください。企業や個人への報復にモデレーションを使わないでください。争いへの個人的な利害を開示し、別のモデレーターに審査を依頼します。公開出典が直接裏付け、アクセス説明に公開が必要な場合を除き、個人を名指ししたり犯罪を主張したりしないでください。
