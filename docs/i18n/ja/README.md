# OpenCoast — オープンソースの海岸アクセスマップ

**ビーチへのアクセス権、海岸までのルート、そしてそれらを裏付ける証拠。**

**アカウント不要。ログイン不要。匿名で閲覧・投稿できます。**

OpenCoast は、**公共のビーチへのアクセスと海岸アクセス権**について、コミュニティで審査された情報を地図に掲載するオープンソースの Web アプリです。海岸エリア、岸辺への道、アクセスポイントを描き、説明、地域の条件、出典を追加して匿名で提出できます。各提案は、公開地図に表示される前にモデレーターが審査します。

[地図を見る](https://opencoast.kaelux.dev/) · [貢献する](CONTRIBUTING.md) · [審査の仕組み](docs/moderation-policy.md) · [開発ガイド](docs/development.md) · [ロードマップ](https://github.com/Ker102/opencoast/issues)

初めての方は、[OpenCoast の目的](https://opencoast.kaelux.dev/about)、[地図の使い方と投稿方法](https://opencoast.kaelux.dev/how-it-works)、[証拠ラベルの意味](https://opencoast.kaelux.dev/evidence)をご覧ください。これらの公開ページは JavaScript なしで読めます。[検索での発見に関する設定と検証](docs/discovery.md)では、サイトの正規 URL、サイトマップ、クローラーポリシーを説明しています。[モーション草案と録画ガイド](../../../tools/motion/README.md)では、プロジェクトの編集可能な動画を説明しています。

> **初期段階のプロジェクトです。** 地図は世界中の移動と投稿に対応しています。審査済み情報は場所ごとに増えていきます。印のない海岸は、**審査済みのアクセス情報がまだない**ことを意味します。立ち入り禁止やアクセスの保証を意味することはありません。

<a id="why-opencoast-exists"></a>

## OpenCoast が存在する理由

地図でビーチを見つけても、疑問は残ります。どのようなアクセスが許可されているのか。どの条件が適用されるのか。到達するための審査済みルートがあるのか。その情報を裏付ける出典は何で、いつ確認されたのか。

OpenCoast は、これらの疑問を一つの地図にまとめます。各レコードは、特定の場所を説明、管轄区域、アクセス状態、証拠ラベル、審査履歴と結び付けます。住民、海岸を訪れる人、コミュニティの地図作成者、出典を調べる人、公共の利益に資する地図ツールを作る開発者に役立つプロジェクトです。

**[Kristofer Jussmann (Ker102)](https://github.com/Ker102)** が作成した OpenCoast は、モンテネグロの海岸アクセスへの懸念から始まりました。対象は世界全体です。[最初のモンテネグロのレコード](https://github.com/Ker102/opencoast/issues/5)は出典審査の取り組みであり、法的結論を事前に読み込んだデータセットではありません。

<a id="anonymous-by-default"></a>

## 標準で匿名

OpenCoast は、身元を明かさずに海岸アクセス情報を利用できることを目指しています。アカウント、ログイン、氏名、メールアドレスなしで、地図の閲覧、場所の提出、訂正の提案、審査の追跡ができます。進捗確認とモデレーターへの回答のために、非公開の受付リンクを保管してください。

アップロードされた証拠の原本はモデレーターだけが閲覧できます。別途承認され、公開への同意がある画像だけが公開表示できます。公開したい説明や証拠に個人情報を含めないでください。モデレーター用ツールには別のログインが必要です。

<a id="what-can-you-map"></a>

## 何を地図に登録できるか

| レコードの種類 | 内容 | 個別に扱う理由 |
| ------------------ | --------------------------------------------------- | -------------------------------------------------------------------------------------- |
| **アクセスエリア** | ビーチ、潮間帯、その他の範囲を定めた海岸エリア | 条件は海岸全体ではなく特定のエリアに適用される場合があります。 |
| **岸辺へのルート** | 道、進入ルート、海岸沿いの通路 | エリアのアクセス状態は、そこに至る土地を横断する許可を確定しません。 |
| **アクセスポイント** | 入口、門、標識、その他の関連する場所 | 正確な地点は、アクセス条件や観察がどこに適用されるかを説明できます。 |

レコードには地域の分類、許可される活動、条件、出典リンク、観察を含められます。賃貸されたビーチやコンセッションは、個別の条件と証拠に基づいて説明できます。OpenCoast は一つのラベルがその場所のすべての権利を決めるとは想定しません。

<a id="what-works-now"></a>

## 現在使える機能

- **レスポンシブな世界地図：** デスクトップやモバイルのブラウザーで閲覧できます。OpenFreeMap が提供する OpenStreetMap 由来のベースマップを使用します。
- **地形を示す Focus ビュー：** 中立的な陸地の色と陰影によって海岸線を読みやすく保ち、審査済みのエリア、ルート、ポイントを際立たせます。
- **精密な描画ツール：** 点、線、多角形の作成と編集、頂点の調整、変更の取り消し、提出前の形状確認ができます。
- **匿名の投稿：** アカウントを作らず情報や訂正を提出できます。非公開の受付リンクを保存して、審査を追跡しモデレーターの質問に回答できます。
- **証拠と日付：** アクセス状態と証拠の強さを区別し、編集日と出典審査日を別々に表示します。
- **モデレーションを経た公開：** モデレーターは追加説明の依頼、監査理由付きの文言修正、承認・却下、非公開証拠の確認ができます。公開レコードには改訂履歴があります。
- **審査済みのエリアとルートの関連付け：** モデレーターは海岸エリアを個別の接近ルートのレコードに関連付けられます。検証済み陸路のラベルは、関連ルートの現在の公開状態、証拠、アクセス状態によって決まります。

<a id="how-to-read-coastal-access-information"></a>

## 海岸アクセス情報の読み方

<a id="access-status"></a>

### アクセス状態

| 状態 | OpenCoast での意味 |
| --------------- | --------------------------------------------------------------------------- |
| **許可** | 審査済みの主張が、レコードの対象範囲でアクセスを許可すると説明しています。 |
| **条件付き** | 記載された制限や条件に従うアクセスを説明しています。 |
| **制限あり** | アクセスに対する制限を説明しています。 |
| **争いあり** | 主張に異議がある、または信頼できる証拠が矛盾しています。 |
| **不明** | 利用可能な情報では、適用されるアクセス規則を確定できません。 |

状態だけでなく説明と条件も読んでください。アクセスラベルは範囲を定めて審査された主張であり、すべての活動や日付に対する保証ではありません。

<a id="evidence-strength"></a>

### 証拠の強さ

**文書による裏付けあり**は、モデレーターがリンクされた公的出典を少なくとも一つ、主張と形状に照らして確認したことを意味します。説明では、出典が何を裏付けるのか、どの不確実性が残るのかを示す必要があります。

**コミュニティ審査済み、公的出典の検証なし**は、公的出典を検証せずにモデレーターが情報の表示を承認したことを意味します。これらのレコードには目に見えるラベルが付き、法的に検証されたアクセス権として解釈してはいけません。

手描きの境界は概略として表示されます。編集日は、法律上の出典を新たに審査したことを意味しません。審査基準の全体は[モデレーション方針](docs/moderation-policy.md)をご覧ください。

<a id="contribute-beach-access-information"></a>

## ビーチのアクセス情報を投稿する

1. **[公開地図](https://opencoast.kaelux.dev/)で場所を見つけます。** 移動・拡大縮小するか、`latitude, longitude` を入力します。地名検索は[計画中](https://github.com/Ker102/opencoast/issues/6)です。
2. **Add information を選び**、エリア、ルート、ポイントを描きます。既存レコードへの訂正も提案できます。
3. **主張を説明します。** 管轄区域、役立つ場合は地域の分類、条件、観察または読んだ内容を含めてください。
4. **出典と証拠を追加します。** 公的文書と直接リンクを強く推奨しますが、必須ではありません。原本はモデレーターだけが閲覧でき、別途承認と公開同意のある画像だけが公開できます。
5. **非公開の受付リンクを保存します。** モデレーターが提案を審査し、公開前に追加説明を求める場合があります。

海岸アクセスの報告はアプリの審査フローで行ってください。GitHub issue はソフトウェアの不具合、文書、機能提案に使用します。両方の方法は[貢献ガイド](CONTRIBUTING.md)をご覧ください。

<a id="frequently-asked-questions"></a>

## よくある質問

<a id="is-opencoast-a-worldwide-database-of-legally-verified-public-beaches"></a>

### OpenCoast は法的に検証された公共ビーチの世界的データベースですか？

OpenCoast は世界地図と異なる管轄区域からの投稿に対応しています。掲載範囲は提出・審査されたレコードに依存し、公的出典の検証がない公開レコードもあります。初期段階の情報プロジェクトであり、完全な法律データベースでも法的権威でもありません。

<a id="does-a-blank-map-mean-a-beach-is-private-or-closed"></a>

### 空白の地図はビーチが私有地または閉鎖中であることを意味しますか？

いいえ。その場所に審査済みのアクセス情報が表示されていないことを意味します。ベースマップの公園、道路、ビーチ、陸地の色は地理的な背景であり、OpenCoast のアクセスに関する主張ではありません。

<a id="can-i-submit-without-an-account-or-an-official-document"></a>

### アカウントや公的文書がなくても提出できますか？

はい。一般の提出にアカウントは不要で、公的出典は推奨ですが必須ではありません。すべての提出にモデレーターの審査は必要です。公的出典を検証していなければ、公開レコードにその旨が表示されます。

<a id="how-is-a-public-beach-connected-to-its-access-route"></a>

### 公共ビーチとアクセスルートはどう関連付けられますか？

ビーチエリアとルートは別のレコードとして審査されます。モデレーターが形状と出典を確認した後、明示的に関連付ける必要があります。近くの道路や道がビーチに届くように見えるだけで、OpenCoast がアクセスルートを推定することはありません。

<a id="does-submitting-to-opencoast-edit-openstreetmap"></a>

### OpenCoast に提出すると OpenStreetMap が編集されますか？

いいえ。OpenCoast は審査済みアクセスレコードを独自のデータベースに保存します。OpenFreeMap が OpenStreetMap 由来の背景地図を提供します。ここでの提出は OpenStreetMap に自動で書き込まれません。

<a id="is-the-coastal-access-data-open-data"></a>

### 海岸アクセスデータはオープンデータですか？

ソフトウェアは MIT ライセンスのオープンソースです。ホストされたデータベースの承認済みレコードには、まだオープンデータのライセンスがありません。再配布前に許可を得てください。非公開証拠と第三者の出典資料には別の権利があります。[ライセンスと帰属表示](#licensing-and-attribution)をご覧ください。

<a id="can-i-use-opencoast-on-my-phone"></a>

### スマートフォンで OpenCoast を使えますか？

はい。レスポンシブな Web インターフェースを利用できます。描画はタッチとデスクトップ入力の両方を想定しています。ネイティブモバイルアプリはまだなく、[実機テストとアクセシビリティ審査](https://github.com/Ker102/opencoast/issues/4)は継続中です。

<a id="help-build-opencoast"></a>

## OpenCoast の開発を支援する

さまざまな分野で貢献を必要としています。

- **地域の知識と出典調査：** 範囲を慎重に定めたレコードや訂正を地図から提出してください。関連条項、出典の日付、不確実性を含めます。
- **地図とユーザー体験：** 描画、移動、読みやすい凡例、キーボード操作、タッチ操作を改善してください。
- **ソフトウェアと基盤：** 地理空間クエリ、モデレーションツール、証拠処理、テスト、デプロイの信頼性を支援してください。
- **文書：** 説明と開発者の導入体験を改善してください。翻訳やローカライズの提案を歓迎します。

[CONTRIBUTING.md](CONTRIBUTING.md)を読み、[未解決の issue](https://github.com/Ker102/opencoast/issues)を確認するか、[改善を提案](https://github.com/Ker102/opencoast/issues/new/choose)してください。セキュリティ上の懸念は[非公開の脆弱性報告](https://github.com/Ker102/opencoast/security/advisories/new)で報告してください。

<a id="run-locally"></a>

### ローカルで実行する

現在の CI は Node.js 24 を使用します。Node.js 24+、npm、Docker をインストールしてから実行してください。

```sh
git clone https://github.com/Ker102/opencoast.git
cd opencoast
npm ci
docker compose up -d
npm run db:migrate
npm run dev
```

`http://localhost:5173` を開きます。ローカルデータベースはアクセスを主張するレコードがない状態で起動します。[開発ガイド](docs/development.md#run-locally)では環境設定、ポート、ローカルアップロード、モデレーターアカウント作成を説明しています。

<a id="current-release-limits"></a>

## 現在のリリースの制限

現在の実装は審査後の公開に対応していますが、広範な宣伝の前に残る作業があります。[アップロードと不正利用対策の強化](https://github.com/Ker102/opencoast/issues/3)、[実機でのタッチ操作とアクセシビリティテスト](https://github.com/Ker102/opencoast/issues/4)、[最初のモンテネグロのレコードに対する独立した出典審査](https://github.com/Ker102/opencoast/issues/5)、[地名検索](https://github.com/Ker102/opencoast/issues/6)です。

管轄区域全体の法律がビーチに自動適用されることはありません。報告された妨害と文書で裏付けられた法的権利は別の主張です。OpenCoast のレコードは審査した証拠を説明しますが、出典文書を置き換えたり法的境界を確定したりするものではありません。

[プロジェクト設計](../../../docs/plans/2026-09-24-opencoast-design.md)と[進捗管理](../../../task.md)をご覧ください。`docs/design-reference` の画像は架空の主張例を含む視覚的コンセプトであり、地図データではありません。
