# 参与 OpenCoast 贡献

感谢你改进地图或软件。请清楚区分报告的观察、引用的法律规则和经过版主审核的结论。

<a id="choose-where-to-contribute"></a>

## 选择贡献渠道

| 你希望协助的事项 | 从这里开始 |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 海滩、海岸区域、路线、入口或更正 | [打开地图](https://opencoast-web.vercel.app/)，使用 Add information 或记录的更正操作。 |
| 官方来源和当地通行条件 | 随相关地图陈述提交来源；阅读[审核政策](docs/moderation-policy.md)了解评估方式。 |
| 软件缺陷或功能 | 搜索[已有 issue](https://github.com/Ker102/opencoast/issues)，然后[创建 issue](https://github.com/Ker102/opencoast/issues/new/choose)。 |
| 代码、文档或无障碍 | 阅读[开发指南](docs/development.md)及下方代码贡献步骤。 |
| 安全漏洞 | 使用[私密漏洞报告](https://github.com/Ker102/opencoast/security/advisories/new)。 |

提交地图信息不需要 GitHub 账号。GitHub 用于开发贡献；地图有自己的版主审核流程。

<a id="map-information"></a>

## 地图信息

使用应用中的 **Add information** 来提议区域、路线、点位或更正，无需账号。请提供你能绘制的最准确几何形状、司法管辖区、你认为允许的行为、相关条件，以及观察或阅读内容的描述。强烈建议提供官方文件和直接链接，但并非必需。没有官方来源的提交仍可审核，并使用可见标签说明这一点。保存私人回执链接以跟踪审核并回答版主的问题。

<a id="what-makes-a-useful-submission"></a>

### 怎样的提交有帮助？

- 确定地点，只绘制陈述涉及的区域、路线或点位。
- 说明相关国家或司法管辖区，以及当地分类，例如特许经营区域或海岸步道。
- 描述活动以及条件、日期、季节性限制或不确定性。
- 对于文件，请提供直接来源链接、标题、发布机构、日期，以及可获得的相关条款或页码。说明它支持陈述的哪一部分。
- 对于个人观察，请说明你在何时看到了什么。将观察与有关法律权利的结论区分开。
- 将通往岸边的路线与其到达的海岸区域分别提交。版主会单独审核并明确关联这些记录。

欢迎全球各地的提交。没有官方来源但有用的描述可在审核后以社区审核标签发布。请勿仅根据一般规则，用假设填满大片区域。

请勿在描述或公开 issue 报告中放入他人的姓名、面孔、电话号码或私人联系信息。上传原件仅供版主查看；同意发布图片是可选的，也不保证图片会被发布。

<a id="code-changes"></a>

## 代码更改

1. 开始工作前搜索已有 issue 和 pull request。
2. 对较大的功能或缺陷创建 issue，以便讨论预期行为。
3. 创建分支，进行范围集中的更改，运行[开发指南](docs/development.md#checks)中的相关检查，然后提交 pull request。
4. 说明改了什么、为何修改、测试了什么，以及对无障碍或隐私的影响。

仓库使用 npm workspaces：`shared` 包含数据契约，`api` 负责持久化和审核，`web` 包含地图界面。公共端点绝不能泄露待审提案、回执令牌、原始证据、版主凭据或贡献者身份。新增地图状态必须有对应的图例和详细说明。

法律来源可能有复用限制。请提供链接并用自己的话总结；不要粘贴整部法律，也不要把其他地图的数据复制进此仓库。OpenStreetMap 署名必须保持可见。不要在生产初始数据中添加海岸通行示例陈述。

<a id="reporting-security-issues"></a>

## 报告安全问题

安全问题请使用 GitHub 的私密漏洞报告，而非公开 issue。请包含最小复现，并避免发布真实的回执链接、证据文件或凭据。
