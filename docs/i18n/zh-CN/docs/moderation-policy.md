# OpenCoast 审核政策（初版）

<a id="review-each-claim-as-a-claim"></a>

## 将每项陈述作为陈述审核

地图描述提交的证据所支持的内容。发布前，版主须核实提案的位置、精确几何形状、司法管辖区、措辞、条件和来源链接。被商家要求离开的报告是观察，本身不能证明法律边界或权利。租约或特许经营可能附带条件，但不代表整片海岸无法通行。有文件记录的法律权利与观察到的阻碍可分别记录。

不会仅凭全国性规则就给海岸上色。提交的边界在获得权威几何数据并单独核查之前，仍然是**近似**边界。海滩区域不能确立陆路通行路线。请把路线作为独立记录审核。

接近路线还必须由版主明确关联到区域，并确认路线确实到达该区域。关联具有书面审计理由，出现在区域的公开修订历史中。只有关联路线当前记录可见、有文件支持且标为允许或有条件时，才算经核实的陆路接近路线。社区审核、有争议、受限或未知路线可以作为相关信息显示，但不验证接近路线。如果路线状态改变，区域的陆路标签也会相应更新。移动已关联几何形状前请移除关联，以便重新核查关系。

<a id="evidence-labels"></a>

## 证据标签

- **有文件支持：** 至少一个链接的官方来源已经对照陈述和几何形状核查。在版主说明中引用或概括相关条款。解释不确定的边界和例外。
- **经社区审核，未核实官方来源：** 版主认为描述足够有用，可以展示，但没有核实官方来源。保持可见标签醒目。不要把法律结论描述为确定事实。

通行状态（`allowed`、`conditional`、`restricted`、`disputed`、`unknown`）与证据强度是独立的。文件规定的限制使用**有条件**；可信证据冲突时使用**有争议**；无法确立实际规则时使用**未知**。拒绝提案不表示禁止通行。

<a id="review-steps"></a>

## 审核步骤

1. 阅读完整描述，在合适缩放级别检查绘制要素。确认形状没有覆盖无关土地或水域。
2. 打开来源链接，确定发布机构、日期、范围以及修订或到期情况。记录实际核查的内容。
3. 检查私人上传的相关性、真实性线索、人脸、姓名、位置元数据及发布许可。不要公开原件。应用可以为已同意发布的图片生成去除元数据的 JPEG 副本，但版主仍须检查可见内容。
4. 检查附近已发布记录和待审提案是否重叠或冲突。缺少细节时请求澄清。
5. 必要时修改措辞以提高准确性，并写明审计理由。分别选择通行状态和证据标签。
6. 写一段简短公开说明，解释为何展示该陈述，以及仍有哪些不确定性。完成上述检查后才选择公开图片。批准、附理由拒绝或请求澄清。

对于早期黑山条目和任何有争议陈述，推广前请寻求第二位独立版主核查法律来源和几何形状。重新核查期间暂停受到质疑的记录，或标为有争议。保持来源和审核日期最新；仅有编辑日期并不意味着新的法律审核。

<a id="privacy-and-conflicts"></a>

## 隐私和利益冲突

绝不能公开回执令牌、贡献者身份、私人消息、原始文件或未经批准的照片。不要利用审核报复公司或个人。披露自己在争议中的利益关系，并请另一位版主审核。除非公开来源直接支持该说法且发布对解释通行有必要，否则避免点名个人或指控犯罪。
